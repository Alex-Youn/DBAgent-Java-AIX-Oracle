## 1. 프로젝트 개요

**한 문장 설명**: DBAgent-Java는 Oracle/MySQL·MariaDB·PostgreSQL·MSSQL·CUBRID DB를 대상으로 모니터링·세션 관리·SQL 실행·AI 기반 오류 분석을 제공하는 Spring Boot 웹 애플리케이션이며, 원래 Python으로 만들어졌던 DBAgent를 Java/Spring Boot로 이식한 것이다(`pom.xml`의 `<description>`: "DBAgent (Oracle DB monitoring/AI-DBA) - Java/Spring Boot port").

**주요 기능**
- **DB 모니터링(대시보드)**: Oracle 인스턴스 상태·세션 목록/상세·Lock Holder-Waiter·테이블스페이스/데이터파일·ASH 기반 Active Session 차트·점검 알림(테이블스페이스/FRA/TEMP/잡 실패/무효 객체 등). RDB(MySQL/MariaDB/PostgreSQL/MSSQL/CUBRID) 전용 대시보드 별도 제공.
- **Fleet Overview**: 등록된 모든 인스턴스의 상태를 한 화면에서 동시 조회(계정별로 보이는 DB만).
- **세션 관리**: 세션 목록/상세 조회, 관리자 전용 세션 Kill(장애조치), TM/TX Lock 대기 실시간 모니터링과 Kill.
- **SQL 실행기(SQL 정합성 튜닝)**: 등록된 계정 권한으로 SQL 1문장 실행, 기본 읽기 전용 모드.
- **성능 분석**: 60초 샘플러가 쌓은 수집 저장소(perf 저장소) 기반으로 wait class 추이 → 구간 드래그 → Event별 막대 → 세션 목록까지 드릴다운. 저장 데이터가 없는 구간은 원본 DB(ASH/AWR)에서 조회.
- **AI DBA(AI 챗봇)**: Ollama 연동 챗봇 + 사내 Oracle 오류 사전 검색(ORA 코드 인식), SQL 튜닝 어드바이저/SQL Writer.
- **계정/DB/메뉴 관리**: 관리자 계정관리, DB 접속정보 관리(비밀번호 AES 암호화), 계정별 메뉴/DB 표시 설정.

**목적**: 사내 여러 DB 인스턴스를 하나의 웹 콘솔에서 안전하게(권한 분리·비밀번호 암호화·읽기 전용 기본값) 모니터링하고, 폐쇄망(인터넷 차단) 환경에서도 자체 번들 JDK/Maven/런타임만으로 빌드·배포·운영할 수 있게 하는 것.

**두 프로젝트를 항상 같이 개발한다**
| 구분 | 원본(Main) | AIX 이관본 |
|---|---|---|
| 경로 | `C:\AI-Projects\DBAgent-Java` | `C:\AI-Projects\DBAgent-Java-AIX` |
| Java | 17 | 8 (`maven.compiler.release=8`, var/record/텍스트블록 금지) |
| Spring Boot | 3.3.5 | 2.7.18 |
| DB 저장소(users/metrics/dbconfig/perf) | SQLite(`sqlite-jdbc`) | H2 1.4.200(파일 확장자 `.mv.db`) |
| 운영 환경 | Windows(개발 PC 상시 서비스, `dist\`) | AIX(폐쇄망, `dist-aix\`) — jar만 반입 |

기능 변경은 **원본에서 먼저 만들고 같은 커밋 흐름으로 AIX에도 이식**하는 것이 원칙이다(설계문서 `전체_작업순서_체크리스트.md` "모든 단계 공통" 참고).

## 2. 기술스택

### 2.1 언어·프레임워크
| 항목 | Main | AIX |
|---|---|---|
| 언어 | Java 17 | Java 8 |
| 프레임워크 | Spring Boot 3.3.5 (`spring-boot-starter-parent`) | Spring Boot 2.7.18 |
| 빌드 도구 | Maven(프로젝트 번들, `maven39/`) | 동일 |
| 웹 | `spring-boot-starter-web` (내장 Tomcat) | 동일 |
| DB 접근 | `spring-boot-starter-jdbc` + `JdbcTemplate` (JPA/MyBatis 미사용, SQL 직접 작성) | 동일 |

### 2.2 대상 DB 드라이버 (`pom.xml` 확인)
| DB | Main | AIX |
|---|---|---|
| Oracle | `ojdbc11` (dependencyManagement 버전 `23.5.0.24.07`) | `ojdbc8` (같은 버전) |
| SQLite (앱 자체 저장소) | `sqlite-jdbc 3.46.1.3` | — |
| H2 (앱 자체 저장소) | — | `h2 1.4.200` (Java 8 호환 마지막 버전으로 고정) |
| MySQL/MariaDB | `mariadb-java-client 3.5.1` (db_type=mysql도 이 드라이버 재사용, wire-protocol 호환) | `mariadb-java-client 2.7.9` (3.x는 Java 11+ 요구) |
| PostgreSQL | `postgresql 42.7.4` | `postgresql 42.7.3` |
| MS SQL Server | `mssql-jdbc 12.8.1.jre11` | `mssql-jdbc 12.8.1.jre8` |
| CUBRID | `cubrid-jdbc 11.3.1.0050` (Maven Central 미배포 → `lib/repo`에 벤더링한 프로젝트 로컬 저장소에서 resolve, 두 프로젝트 공용) | 동일 |

### 2.3 주요 라이브러리
- 커넥션 풀: HikariCP(Spring Boot 기본 포함) — Oracle/RDB 각각 별도 풀 매니저(`OracleConnectionPoolManager`, `RdbConnectionPoolManager`)로 인스턴스별 풀 관리.
- 비밀번호 해시(계정 로그인): `spring-security-crypto` (대상 DB 접속 비밀번호 암호화는 별도, 6절 참고).
- JSON: Spring Boot 기본 Jackson(`spring-boot-starter-web`에 포함, 별도 의존성 추가 없음).
- 프런트: 빌드 스텝 없는 정적 HTML/JS(`src/main/resources/static/`) — Chart.js 4.5.1(`lib/chart.js`), `chartjs-adapter-date-fns`, Mermaid(`lib/mermaid.min.js`), Lucide 아이콘(`lib/lucide.js`). npm/webpack 등 프런트 빌드 도구 없음(정적 파일을 그대로 서빙).

### 2.4 설계 특징
- **프로젝트 로컬 Maven 저장소**: CUBRID 드라이버처럼 Maven Central에 없는 아티팩트는 `lib/repo` 아래에 커밋해 두고 `pom.xml`의 `<repositories>`로 resolve — 폐쇄망에서도 `mvn install:install-file` 없이 `mvn clean package`만으로 빌드된다.
- **완전 번들형 배포**: JDK(`jdk17/`), Maven(`maven39/`), jlink로 만든 최소 런타임(`dist/runtime`)을 프로젝트 안에 두고 시스템 Java/Maven에 의존하지 않는다(AIX는 `java8/`를 서버에 별도 배치).
- **DB 저장소 4개로 분리**: `users.db`(계정/세션), `dbconfig.db`(대상 DB 접속정보), `metrics.db`(60초 수집값 `instance_metric_history`), `perf.db`(성능 분석 전용 1분 요약 `perf_ash_min` 등) — 모두 `db_config/` 하위(AIX는 `.mv.db`).

## 3. 핵심 명령어

### 3.1 소스 수정 규칙(빌드 전 필수)
- **항상 두 프로젝트에 같이 반영한다**(Main → AIX 순서, 2절 참고). AIX는 Java 8 문법만 사용 — `var`/`record`/텍스트 블록 금지, `String.isBlank()` 등 Java 11+ 전용 메서드 대신 `com.dbagent.util.Strings`/`Maps`/`Lists`(AIX 전용 유틸, `src/main/java/com/dbagent/util/`)를 쓴다.
- 정적 리소스(`static/*.html`, `*.js`, `*.css`)를 고치면 **캐시버스터(`?v=`) 번호를 올린다** — 브라우저 캐시 충돌 사고가 있었음(번호 재사용 금지, 항상 이전 값보다 크게).
- `application.properties`(루트/`dist/`/`dist-aix/`)는 **git skip-worktree 대상**이라 코드에서 새 설정 키를 추가할 때는 `@Value("${키:기본값}")` 형태로 **기본값을 반드시 지정**한다 — 현장 설정 파일에 그 키가 없어도 기동되게 하기 위함.

### 3.2 빌드 명령
Git Bash 기준, 프로젝트 루트에서:
```bash
JAVA_HOME=$PWD/jdk17 ./maven39/bin/mvn -q -o clean package -DskipTests
```
- **항상 `clean`을 붙인다** — 이전 정적 리소스가 남아 브라우저에 섞여 나간 사고가 있었다.
- PowerShell에서는 `build.ps1`(같은 빌드를 감싸고 실행 중이면 자동 stop/재시작)이 있으나, **`-Dist` 옵션은 경로 버그가 있어 신뢰하지 말 것** — dist 반영은 3.3절 수동 절차로 한다.
- 산출물: `target\dbagent-java-0.1.0.jar`.

### 3.3 배포(운영 반영) 명령
Main(개발 PC 상시 서비스, 포트 8006):
1. `dist\dbagent-java-0.1.0.jar`를 `dbagent-java-0.1.0.jar.bak-YYYYMMDD-HHMM`으로 백업
2. `target\dbagent-java-0.1.0.jar`를 `dist\dbagent-java-0.1.0.jar`로 교체
3. `dist\stop.ps1` → `dist\start.ps1`

AIX(폐쇄망): jar만 반입, 소스/Maven/JDK17은 반입하지 않는다.
```sh
./stop-aix.sh
cp -p dbagent-java-0.1.0.jar dbagent-java-0.1.0.jar.bak-$(date +%Y%m%d-%H%M)
cp <반입한 jar> dbagent-java-0.1.0.jar
./start-aix.sh
```
덮어쓰면 안 되는 것: `application.properties`, `db_config/` 안의 기존 DB 파일, `dbagent.key`(각 문서마다 강조됨). 상세 절차는 `가이드/폐쇄망_적용절차_*.md`(배포 회차별로 파일이 따로 있음, 최신: `폐쇄망_적용절차_2026-09-26_배포6.md`).

### 3.4 기동/종료 명령(개발 PC, Windows)
| 동작 | 명령 |
|---|---|
| 기동 | `.\start.ps1` (또는 `start.bat`) — 번들 JDK17로 jar 실행, `application.properties`의 `server.port` 자동 인식(기본 8005, 이 프로젝트 실서비스는 8006), 기동 완료까지 대기 후 브라우저 자동 오픈 |
| 종료 | `.\stop.ps1` (또는 `stop.bat`) — PID 파일 우선, 없으면 포트로 프로세스 탐색 후 종료 |
| dist(운영 인스턴스) | `dist\start.ps1` / `dist\stop.ps1` — 번들 jlink 런타임(`dist\runtime`) 사용, 시스템 Java 전혀 의존하지 않음 |
| AIX | `./start-aix.sh` / `./stop-aix.sh` — 서버 자체 `java8/` 사용, Maven/빌드 기능 없음(반입한 jar만 실행) |

### 3.5 린트 명령어
**린트 도구가 구성되어 있지 않다.** `pom.xml`에 checkstyle/spotless/PMD 등의 플러그인이 없다(빌드 플러그인은 `spring-boot-maven-plugin`뿐). 대신:
- Java: `mvn clean package`(컴파일 오류만 검출, 스타일 검사 없음) — 위 3.2 명령이 사실상의 정적 검증이다.
- JS(정적 리소스): 별도 린터 없음. 문법 오류만 빠르게 확인하려면 `node -e "new Function(require('fs').readFileSync('경로','utf8'))"` 같은 구문 검사로 대체 가능(파싱만 확인, 스타일/규칙 검사 아님).
- 코드 품질 점검은 `code-inspector`/`query-performance-reviewer`/`security-reviewer` 같은 별도 리뷰 절차(전체 작업순서 체크리스트에 각 단계마다 기록됨)로 대체하고 있다.

### 4.1 최상위 (Main 기준, AIX도 동일 구조 + `dist-aix/`, `start-aix.sh`/`stop-aix.sh` 추가)

| `sqltune-rag/`, `sqltune-rag-java/` | SQL 튜닝 RAG 프로토타입/이관본(별도 관리, git 추적 제외) |
| `security-poc` | 보안 관련 PoC |
| `backup_*/` | 특정 시점 수동 백업 스냅샷(사고 대응용) |
| `산출물/` | 이 문서를 포함한 사용자 대상 산출물(신규, 2026-09-26 확정) |

### 4.2 `src/main/java/com/dbagent/` 패키지
| 패키지 | 역할 |
|---|---|
| `auth` | 로그인/세션(토큰), 계정 CRUD, 권한(admin/일반), 계정별 메뉴·DB 숨김, Fleet Overview 접근 권한 |
| `config` | `DataSourceConfig`(users/metrics/dbconfig/perf 4개 데이터소스 Bean), `SchedulingConfig`, `StaticResourceConfig` |
| `oracle` | 대상 Oracle(및 전체 DB 공통) 접속정보 관리(`DatabaseConfigService`, 암호화 연동), 커넥션 풀(`OracleConnectionPoolManager`), 관리자용 DB 등록/설정 API |
| `monitor` | Oracle 모니터링 핵심 — 대시보드 쿼리(`MonitorService`/`DashboardQueryService`), 60초 샘플러(`InstanceMetricSamplerService`), 수집 저장소(`MonitorStoreService`/`PerfStoreService`), Lock 실시간(`LockRealtimeService`), 점검 알림(`CheckCollector`/`CheckDetailService`), 성능 분석(`PerfAnalysisService`) |
| `rdb` | MySQL/MariaDB/PostgreSQL/MSSQL/CUBRID 전용 모니터링 서비스 + 공용 커넥션 풀(`RdbConnectionPoolManager`) |
| `query` | SQL 실행기(`SqlQueryService`, 읽기 전용 모드 포함), 실행계획(`ExecutionPlanService`) |
| `security` | 대상 DB 비밀번호 암호화(`CredentialCipher`, `MasterKeyProvider`) — 6절 참고 |
| `aidba` | AI 챗봇(`OllamaChatService`), 오류 사전 검색(`ErrorSearchService`) |
| `sqltuneadvisor`, `sqltuning`, `sqlwriter` | SQL 튜닝 어드바이저, 자동 튜닝, SQL 생성/테이블 정보 조회 |

## 5. 코딩 규칙

소스에서 관찰되는 관례를 정리한 것이며, 강제하는 린터는 없다(3.5절).

- **한글 주석에 날짜와 근거를 남긴다**: `// 2026-09-25 결정: ...`, `/** ... (설계문서 `...md` N절) */` 형태로 "왜 이렇게 했는지"와 "언제·누가 결정했는지"를 주석에 남기는 관례가 전 코드베이스에서 일관되게 나타난다(예: `CredentialCipher.java`, `nd-lock.js` 상단 주석). 새 코드도 이 관례를 따른다.
- **Main→AIX 동기화**: 기능 변경은 항상 두 프로젝트에 반영한다(1·3.1절). AIX 전용 커밋에서만 Java 8 대체(`var`/`record`/텍스트 블록 금지, `Strings.isBlank()` 등은 `com.dbagent.util` 유틸 사용).
- **줄바꿈**: 파일이 CRLF(`\r\n`)로 저장되어 있다(`pom.xml`, `application.properties` 등 확인됨, Windows 개발 환경 기준) — 기존 파일 편집 시 개행 문자를 섞지 않는다.
- **HTML 이스케이프**: 세션 상세 등 사용자/DB에서 온 값을 화면에 뿌릴 때는 항상 이스케이프한다(`session-detail.html`: "값은 전부 HTML 이스케이프", `dbagent-common.js`의 `esc()` 계열 헬퍼를 공용으로 사용).
- **바인드 변수 사용**: SQL 실행은 `JdbcTemplate`의 `?` 바인드 변수를 쓴다(`AshRange.Filter` 등). 단, 관리자가 직접 실행하는 SQL 실행기(4절 query 패키지)는 성격상 예외 — 대신 읽기 전용 모드(6절과 별개, `dbagent.sql-runner.read-only`)로 방어한다.
- **설정 키는 기본값을 갖는다**: `@Value("${키:기본값}")` — 운영 현장의 `application.properties`에 새 키가 없어도 기동되게 한다(3.1절).
- **KILL 등 위험 동작은 재조회 후 실행**: 세션 Kill처럼 되돌릴 수 없는 동작은 "요청 시점"이 아니라 "실행 직전"에 대상 세션을 다시 조회해 끝났거나 SERIAL#이 바뀐 세션, BACKGROUND, 앱 자신은 건너뛰고, 성공/건너뜀/실패를 모두 감사 테이블(`mon_kill_audit`)에 남긴다.
- **정적 리소스 캐시버스터**: HTML의 `<script src="app.js?v=174">` 형태 버전 번호를 파일 수정 시 올린다(3.1절).
- **네이밍**: 클래스는 역할 접미사를 붙인다(`*Controller`, `*Service`, `*Request`) — 별도 DTO 패키지 없이 각 기능 패키지 안에 함께 둔다. REST 경로/쿼리 파라미터는 `db_id`, `sql_id`처럼 스네이크 케이스를 쓰는 반면 Java 필드/메서드는 카멜 케이스를 쓴다(프런트-백엔드 계약을 스네이크 케이스로 통일한 기존 관례를 유지, 신규 API도 동일하게 맞춘다).

## 6. 보안(암호화) 방식

전체 설계는 `설계문서/비밀번호_암호화_설계_2026-09-21.md`, 구현은 `src/main/java/com/dbagent/security/`(`CredentialCipher.java`, `MasterKeyProvider.java`).

### 6.1 대상 DB 접속 비밀번호 암호화
- **알고리즘**: AES/GCM/NoPadding. 암호화마다 `SecureRandom`으로 12바이트 IV를 새로 생성(IV 재사용 금지 — GCM에서 키 복구로 이어질 수 있음), 128비트 인증 태그.
- **저장 포맷**: `ENC(v1:<keyId>:<base64(IV 12B ‖ ciphertext ‖ tag 16B)>)`. AAD로 `v1:<keyId>` 헤더를 넣어 버전/키ID 변조도 태그 검증 대상에 포함시킨다.
- **레거시 호환**: 기존 `B64(...)` 래퍼(단순 Base64, 실질적 비암호화)는 복호화 시 그대로 디코드하고, 그 외 값은 평문으로 간주 — 마이그레이션이 일부만 끝난 혼재 상태에서도 앱이 정상 동작한다. `needsReencrypt()`로 기동 시 멱등 재암호화 스캔(`DatabaseConfigService.reencryptAllPasswords`)을 수행한다.
- **저장 위치**: `dbconfig.db`(Main, SQLite) / `dbconfig.mv.db`(AIX, H2)의 `accounts` JSON 배열 안 등 비밀번호가 들어가는 모든 자리에 같은 규칙 하나로 적용(별도 컬럼 추가 없음).

### 6.2 마스터 키 관리
- **키 소스 우선순위**: 환경변수 `DBAGENT_MASTER_KEY`(`<keyId>:<base64키>` 형식) → `dbagent.security.key-file`이 가리키는 파일 → 둘 다 없으면 **최초 기동 시 자동 생성**(파일: 프로젝트 루트/앱 폴더의 `dbagent.key`, 형식은 Java `Properties` — `active`, `key.<id>`, `created.<id>`).
- **자동 생성을 기본 경로로 둔 이유**: 2026-08-18에 AES를 한 번 구현했다가 "키 생성/서버별 환경변수 등록"의 운영 부담 때문에 롤백한 전례가 있어(`수정내역/커넥션풀_암호화_수정내역_2026-08-18.md`), 운영자가 아무것도 하지 않아도 기동되게 만들었다.
- **키 길이 자동 폴백**: 이 JVM이 AES-256을 허용하면 32바이트(256bit) 키, `getMaxAllowedKeyLength()`가 256 미만이면 16바이트(128bit)로 자동 생성 — 폐쇄망 IBM J9 Java 8이 무제한 정책 파일 없이 AES-256을 거부해 기동이 막히는 것을 방지. 반대로 키 파일의 키 길이가 이 JVM에서 허용되지 않으면 조용히 넘어가지 않고 기동을 막는다.
- **파일 보호**: POSIX(AIX/Linux)에서는 저장 직후 권한을 600(소유자만 읽기/쓰기)으로 제한. Windows는 POSIX 뷰가 없어 건너뛰고 경고 로그만 남긴다.
- **git 제외**: `dbagent.key`, `*.key`는 `.gitignore`에 등록되어 있고, 각 서버가 자기 키를 자동 생성해 쓴다(git으로 전파하지 않음). 키 파일 상단 주석에도 "git 커밋 금지 / dbconfig.db와 같은 매체에 백업 금지"가 명시되어 있다.
- **키 로테이션/이관 시 실패 처리**: 해당 `keyId`가 이 서버에 없으면(다른 서버 DB 파일을 키 없이 가져온 경우 등) 명확한 예외를 던진다 — 실측상 두 서버가 키를 자동 생성하면 `keyId`가 똑같이 `k1`이 되어 "키 없음"이 아니라 인증 태그 불일치로 실패하는 경우가 더 흔하므로, 예외 메시지에 그 가능성을 명시한다.
- **AIX 포팅 제약**: `CredentialCipher`/`MasterKeyProvider` 모두 Java 8 문법만 사용(주석에 명시).

### 6.3 인증/권한
- **로그인 계정 비밀번호**: `spring-security-crypto`로 해시(대상 DB 비밀번호와는 별개 체계).
- **세션/토큰**: 로그인 성공 시 발급한 토큰을 브라우저 `sessionStorage`에 저장(`dbagent_token`), API 호출 시 `token` 파라미터로 전달. 서버는 `AuthService.sessionForToken()`이 매 호출마다 TTL(`dbagent.auth.session-ttl-days`, 기본 30일)을 재확인하고, 매일 새벽 3시 배치(`cleanupExpiredSessions`)로 만료 토큰 행을 정리한다. 재기동 시 `sessions` 테이블을 통째로 비운다.
- **권한 분리**: `admin`/일반 역할(`AuthService.isAdmin`), 계정별 숨김 메뉴·숨김 DB 목록, `canAccessDb(token, dbId)`(admin이거나 숨김 목록에 없으면 허용), `canAccessFleetOverview(token)`(admin은 항상 허용, 그 외는 `fleet_overview` 컬럼으로 개별 부여). 거의 모든 모니터링/조회 API가 컨트롤러 진입 시점에 `canAccessDb`를 먼저 확인한다.
- **세션 Kill 보안 강화(2026-09-26)**: 기존 `/api/kill_session`을 포함한 모든 Kill 경로가 (1) `isAdmin` 확인 (2) `canAccessDb` 확인(관리자라도 허용 DB 밖은 거부) (3) 실행 직전 재조회로 끝났거나 SERIAL#이 바뀐 세션/BACKGROUND/앱 자신을 "건너뜀" 처리 (4) 결과를 전부 `mon_kill_audit`에 기록하도록 보강되었다.
- **SQL 실행기 읽기 전용 모드**: `dbagent.sql-runner.read-only`(기본 `true`) — 첫 키워드가 `SELECT`/`WITH`가 아니면 서버에서 거부하고, 허용된 조회도 실행 중 `SET TRANSACTION READ ONLY`로 2차 방어한다(예: `SELECT ... FOR UPDATE`는 이 방어에서 ORA-01456으로 차단됨). `false`로 끄면 이전처럼 모든 SQL(DML/DDL 포함, 자동 커밋)이 실행된다 — 운영 환경에서 끄는 것은 의도적 결정이 필요하다.

  - 60초 샘플러가 매분 (대기 분류, Event, 계정, 서버, SQL)별 대기 시간을 `perf_ash_min` 테이블(Main: `db_config/perf.db` SQLite, AIX: `db_config/perf.mv.db` H2)에 append.
  - 보관 기간 `dbagent.monitor.perf-retention-days`(기본 **15일**), 매일 새벽 배치로 시간 단위 삭제.
  - 메뉴 진입 시 기본 최근 15분(DB 시각)을 자동 조회. 저장소에 데이터가 없는 구간(배포 전, 앱 정지 기간)은 "원본 DB(ASH/AWR)에서 조회" 버튼으로 대체 조회.
  - 함께 바뀐 값: 60초 수집값(`instance_metric_history`) 보관 기간도 기본 **30일 → 15일**로 단축.
- **G4. 나머지 팝업 G2 스펙 적용**: 세션 목록, 테이블 정보, 데이터파일, ERD(1200×800만 예외), 환경설정 팝업 3개.
- **부수 반영**: 새 대시보드 Lock 카드 색을 TX 보라(`#7c3aed`)/TM 붉은색(`#be123c`)으로 정정, 대기 세션 기준을 **TX 5건 주의·10건 위험 / TM 3건 주의·6건 위험**으로 조정(TM은 테이블 단위라 한 건이 여러 세션을 막을 수 있어 더 낮게 잡음, 1건만으로는 "주의" 아님). 점검 알림 ⑧에서 "통계 오래됨" 항목 제거.

## 확인하지 못한 사항 / 추가 확인 필요

- **폐쇄망(AIX 실서버) 실측값**: ASH/AWR 실제 보관 기간, 60초·성능 분석 샘플링 소요 시간, 저장소 파일 실제 증가 속도, Oracle 11g에서의 `/top` 쿼리 동작 — 모두 개발 PC(로컬 Oracle XE, JDK 17 기동)에서만 검증되었고 현장 실측이 필요하다고 체크리스트에 명시되어 있다.
- **RAC 환경에서의 `sample_id` 워터마크 정확성**: 코드 주석상 인스턴스 로컬 값이라 `connect_mode=service`(SCAN 로드밸런싱) 등록이면 사이클마다 다른 노드에 붙을 수 있다는 우려가 남아 있으며, 폐쇄망 등록값 확인이 필요하다고 기록되어 있다(코드로 이 프로젝트의 실제 등록 방식까지는 확인하지 못함).
- **H1(쿼리 성능 체크 문서)의 최신 내용**: 다른 작업자가 동시에 `설계문서/쿼리_성능_체크_기능별.md`를 작성 중이라는 사실은 오케스트레이터 지시로 파악했을 뿐, 해당 문서 자체는 이번 작업 범위에서 읽지 않았다.
