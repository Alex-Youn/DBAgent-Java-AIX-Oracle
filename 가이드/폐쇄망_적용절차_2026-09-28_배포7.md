# 폐쇄망 적용 절차 (2026-09-28) — 배포 ⑦ 헬스체크 Busy/Not Alive 오판·고착 수정

> 대상: 대시보드 상단 인스턴스/리스너 Alive 표시(`/api/health`)의 오판·고착 버그 수정 3건
> 적용 내용: **jar 교체만.** 새 저장소 파일 없음, DB 스키마 변경 없음. 설정 키는 1개 추가(선택, 없으면 기본값 30초).

## 무엇이 바뀌나

| 구분 | 내용 |
|---|---|
| 증상 | DB가 실제로 다운돼도 대시보드 상단 인스턴스/리스너가 `Alive`로 계속 떠 있거나, `Busy`(주황)로 몇 분씩 눌러붙어 있다가 뒤늦게 `Not Alive`(빨강)로 바뀌는 문제(오케스트레이터 실측, 로컬 Oracle 컨테이너 정지로 재현) |
| 원인 1 | 대시보드가 2초 주기로 헬스체크 포함 5종 API를 매번 동시에 호출 - DB가 죽으면 이 동시성 자체가 HikariCP의 "다른 요청도 대기 중"(`waiting>0`) 신호를 만들어, 진짜 다운을 "일시적 풀 경합"(Busy)으로 오판. 재시도할 때마다 같은 오판이 반복되면 `Not Alive` 전환이 몇 분씩 밀림 |
| 원인 2 | 신규 대시보드(벤토형)의 상태바 갱신 함수에 실패 처리(try/catch)가 없어, 앱 서버 자체가 죽으면 화면이 마지막으로 성공했을 때의 `Alive`를 그대로 띄운 채 멈춤(콘솔에만 에러 로그) |
| 수정 1 | 헬스체크를 먼저 단독으로 보내고, 살아있을 때만 나머지 4종을 쏘도록 순서 변경 - 죽은 DB에 대한 헬스체크가 거의 항상 단독 요청이 되어 첫 시도(수백ms~수 초) 만에 진짜 실패로 정확히 판정됨 |
| 수정 2 | 그래도 Busy가 연속 30초(`dbagent.monitor.health-busy-max-seconds`, 기본값) 넘게 안 풀리면 서버가 강제로 `Not Alive`로 확정하는 세이프티넷 추가 |
| 수정 3 | 신규 대시보드 상태바에도 실패 처리 추가 - 서버가 죽으면 즉시 `Not Alive`로 표시 |
| 검증 방식 오해 방지 | Busy는 여전히 정상적으로 뜰 수 있다(진짜 풀 경합 상황) - 이번 수정은 "DB가 실제로 죽었는데도 Busy/Alive에 눌러붙어 있는" 상황만 없앤다 |

## 1. 앱 jar 교체

```bash
./stop-aix.sh
ps -ef | grep dbagent-java | grep -v grep        # 아무것도 안 나와야 정상
cp -p dbagent-java-0.1.0.jar dbagent-java-0.1.0.jar.bak-$(date +%Y%m%d-%H%M)
cp <반입한 jar> dbagent-java-0.1.0.jar
./start-aix.sh
```

**덮어쓰지 말 것**: `application.properties`, `db_config/` 안의 기존 파일, `dbagent.key`.

새 저장소 파일이나 DB 스키마 변경이 없으므로 `db_config` 백업은 이번엔 불필요.

## 2. 새 설정 키 (선택, `application.properties.sample`에 전체 목록)

| 키 | 기본값 | 설명 |
|---|---|---|
| `dbagent.monitor.health-busy-max-seconds` | 30 | 헬스체크 Busy 세이프티넷 - 이 시간 이상 연속 Busy가 지속되면 강제로 Not Alive 확정 |

값을 넣지 않으면 30초로 동작. 폐쇄망 네트워크/DB 응답이 원래 느려 정상적인 풀 경합이 30초 넘게 이어지는 인스턴스가 있다면 늘려서 조정.

## 3. 확인

F12 → Network에서 `app.js?v=174`, `nd-dashboard.js?v=6` (AIX). 옛 번호면 Ctrl+F5.

| 확인 | 기대 결과 |
|---|---|
| 정상 상태 | 대시보드/신규 대시보드 상단 인스턴스·리스너 모두 `Alive`(파란색) |
| DB 인스턴스 강제 종료(테스트 가능하면) | 몇 초~십수 초 안에 `Not Alive`(빨강)로 전환. 예전처럼 몇 분씩 `Busy`(주황)에 눌러붙지 않아야 함 |
| DB 복구 | 플래핑 없이 다시 `Alive`로 안정적으로 복귀 |
| 앱 서버 자체를 내린 상태에서 화면을 열어둔 경우 | (신규 대시보드 포함) 곧바로 `Not Alive`로 표시, 화면에 이전 `Alive`가 남아있지 않아야 함 |

## 4. 현장 실측 부탁

| 항목 | 방법 | 이유 |
|---|---|---|
| Busy 세이프티넷 30초 기본값이 폐쇄망 환경에도 맞는지 | 정상 운영 중 대시보드에 `Busy`가 뜨는 빈도·지속시간 관찰 | 개발 PC는 로컬 Docker Oracle이라 응답이 빨라, 폐쇄망의 실제 네트워크 지연 하에서 정상적인 풀 경합이 30초를 넘길 가능성을 배제 못 함 - 넘기면 위 설정 키로 늘림 |

## 5. 롤백

```bash
./stop-aix.sh
cp -p dbagent-java-0.1.0.jar.bak-<1절 시각> dbagent-java-0.1.0.jar
./start-aix.sh
```

새 저장소 파일이 없으므로 jar만 되돌리면 끝.
