# 폐쇄망 적용 절차 (2026-09-26) — 배포 ⑥ 세션 상세·팝업 통일·성능 분석

> 대상: 전체 작업순서 **G단계(G1~G4)** + 기존 Kill 보안 보강 + 성능 분석 수집 저장소 전환 + 당일 요청 반영(Lock 기준·색, 점검 알림 정리)
> 배포 ①~⑤를 아직 적용하지 않았다면 이번 jar에 모두 포함되어 있다. 배포 ② 절차서의 2절(sqlrestapi prompt 복사)만 추가로 하면 된다.
> 적용 내용: **jar 교체만.** 새 저장소 파일(`db_config/perf.mv.db`)은 앱이 기동할 때 스스로 만든다. 설정 키는 전부 선택(없으면 기본값).

## 무엇이 바뀌나

| 구분 | 내용 |
|---|---|
| 성능 분석 (구 "성능 이력 조회") | 메뉴 이름 변경. 산점도 대신 **상단 wait class 막대 → 드래그로 구간 선택 → 하단 Event별 막대 → 막대 클릭 시 세션 목록 팝업** |
| 성능 분석 데이터 | **수집 저장소에서 읽는다** — 60초 샘플러가 매분 (대기 분류, Event, 계정, 서버, SQL)별 대기 시간을 `db_config/perf.mv.db`에 쌓는다(15일 보관). 화면을 열어도 운영 DB로 조회가 가지 않는다 |
| 성능 분석 초기 화면 | 메뉴에 들어오면 최근 15분(DB 시각)을 바로 조회. 계정·서버 목록도 저장소에서 |
| 원본 DB 조회 | 저장소에 데이터가 없는 구간(배포 전, 앱이 꺼져 있던 시간)만 **"원본 DB(ASH/AWR)에서 조회"** 버튼으로 |
| 세션 상세 팝업 | 가로형, SID.SPID ~ Hash Value 12칸 표, 탭 **SQL Text / DBMS Plan / Bind Variable** |
| 팝업 통일 | 모든 팝업(환경설정 3개 포함) 기본 1100×680, 본문과 같은 90% 배율, 같은 제목 줄. ERD만 1200×800 |
| Kill 보안 | 기존 대시보드·Current Session·TM Lock 탭의 Kill/장애조치: DB 접근 권한 확인, **실행 직전 재조회**(끝났거나 SERIAL# 바뀐 세션·BACKGROUND·앱 자신은 "건너뜀"), 결과 전부 감사 기록 |
| 새 대시보드 Lock 카드 | 색 **TX 보라 / TM 붉은색**. 대기 세션 기준 **TX 5건 주의·10건 위험, TM 3건 주의·6건 위험**(1건만으로는 주의 아님) |
| ⑧ 점검 알림 | "통계 오래됨" 항목 제거(기존 결과도 기동 시 삭제) |
| 보관 기간 | 60초 수집값(`instance_metric_history`) 기본 **30일 → 15일** |

## 1. 앱 jar 교체

```bash
./stop-aix.sh
ps -ef | grep dbagent-java | grep -v grep        # 아무것도 안 나와야 정상
cp -p dbagent-java-0.1.0.jar dbagent-java-0.1.0.jar.bak-$(date +%Y%m%d-%H%M)
cp -rp db_config db_config.bak-$(date +%Y%m%d-%H%M)   # 새 저장소 파일이 생기고 보관 기간이 줄어드므로 백업(롤백용)
cp <반입한 jar> dbagent-java-0.1.0.jar
./start-aix.sh
```

**덮어쓰지 말 것**: `application.properties`, `db_config/` 안의 기존 파일(`users.mv.db`, `metrics.mv.db`, `dbconfig.mv.db`), `dbagent.key`.

기동 직후 등록된 DB마다 최근 60분을 ASH에서 한 번 채운다(기동 때만 잠깐 조회가 더 나감).

## 2. 보관 기간 확인 (중요)

60초 수집값의 기본 보관 기간이 **15일로 줄었다.** 다음 새벽 03:45 정리 때 15일보다 오래된 수집값이 지워진다(되돌릴 수 없음 - 1절의 `db_config` 백업으로만 복구).

```bash
grep -i retention application.properties
```

- 아무것도 안 나오면 새 기본값(15일)이 적용된다.
- 30일을 유지하려면 `dbagent.monitor.metric-retention-days=30`을 넣는다. 다만 성능 분석 저장소는 15일이라, 15일보다 오래된 구간은 상단 차트만 보이고 Event 막대·세션 목록은 비게 된다.

## 3. 새 설정 키 (선택, `application.properties.sample`에 전체 목록)

| 키 | 기본값 | 설명 |
|---|---|---|
| `dbagent.monitor.perf-retention-days` | 15 | 성능 분석 저장소 보관 기간(매일 04:15 삭제) |
| `dbagent.monitor.metric-retention-days` | 15 (예전 30) | 60초 수집값 보관 기간(매일 03:45 삭제) |
| `dbagent.perf.datasource.url` | 없음 | 성능 분석 저장소 위치. 없으면 metrics 설정에서 이름만 바꿔 `./db_config/perf`(파일 `perf.mv.db`) |

## 4. 확인

F12 → Network에서 `app.js?v=173`, `style.css?v=56`, `perf-analysis.js?v=4`, `popup.css?v=2`, `nd-lock.js?v=5`, `dbagent-common.js?v=13` (AIX). 옛 번호면 Ctrl+F5.

| 확인 | 기대 결과 |
|---|---|
| 기동 로그 | `perf - Start completed`, DB마다 `perf backfill for db_id=... : N row(s)`. `perf store write failed`·`perf backfill skipped` 경고가 없어야 함 |
| `db_config/perf.mv.db` | 기동 후 생기고, 몇 분 뒤 크기가 조금씩 늘어남 |
| 성능 분석 메뉴 | 조회 버튼 없이 최근 15분 차트·Event 막대가 뜸, "데이터 **수집 저장소(1분 요약)**" 표시 |
| 성능 분석 드래그·막대 클릭 | 하단이 선택 구간으로 바뀜 / Event 세션 목록 팝업(계정·서버·SQL 조합) → 행 클릭 시 세션 상세 |
| 배포 전 구간 조회 | "이 구간에 수집 데이터가 없습니다" + **원본 DB(ASH/AWR)에서 조회** 버튼 |
| 세션 행 클릭(Current Session 등) | 가로형 세션 상세, 12칸 표, 탭 3개 |
| 톱니 → 계정/DB/메뉴 표시 설정 | 다른 팝업과 같은 크기·틀 |
| 새 대시보드 Lock 카드 | TX 보라·TM 붉은색, 대기 1~4건(TX)·1~2건(TM)은 "정상" |
| Kill 결과 창 | 성공 / **건너뜀** / 실패 건수와 사유 |

## 5. 현장 실측 부탁

| 항목 | 방법 | 이유 |
|---|---|---|
| 60초 수집 시간 | 로그에 `perf sampling skipped`(제한시간 10초 초과 등)가 반복되는지 | 운영 규모에서 분 단위 묶음 쿼리가 10초 안에 끝나는지 |
| 저장소 크기 | 하루 뒤 `ls -l db_config/perf.mv.db` | 활성 세션·SQL 종류가 많은 DB에서 15일치 용량 예측 |
| AIX Java 8 기동 | 기동 로그에 예외가 없는지 | 개발 PC에서는 JDK 17로만 실행 확인함 |
| Kill 권한 | 관리자 계정으로 테스트 세션 Kill | 수집 계정에 `ALTER SYSTEM` 권한이 없으면 FAILED로 감사 기록 |
| (배포 ⑤ 5절 미완 항목) | 11g `/top`, 1일 점검 소요 시간, 수집 계정 권한, RAC connect_mode | 그대로 유효 |

```bash

cp -p dbagent-java-0.1.0.jar.bak-<1절 시각> dbagent-java-0.1.0.jar
```
